# Python 逐函数复核与修正

用户要求主动对照每个函数检查，避免继续依赖用户逐段指出。使用 `python-coding-guidelines`，在现有修改上完成全部第一方 Python 文件的函数、异步函数、方法、嵌套函数与 lambda 审核；无函数的文件也核对其模块职责和声明。

1. 用 AST 建立真实函数清单及源码指纹，固定两个子代理和主代理互不重叠的文件写入范围。原有审核报告仅作线索，不替代当前函数正文、调用者和契约的阅读。
2. 为每个函数记录其实际职责/输入输出、适用规则、具体判断和修改或保留理由。不能批量生成“符合”的空结论，也不能以 lint 通过、删掉 try/None 或函数行数作为语义结论。
3. 按 NAM、FUN/CLS、DAT、ERR/RES、ASY/WEB/PYD、LOG、DB、DES、TST 中实际适用的规则检查。额外复核主流程是否顺序可读、平台/业务策略是否交错、是否存在无职责包装、重复默认值、装饰输出或猜测性保护。
4. 先删除已确认无用内容，再改保留实现；不因风格改变业务、接口、框架协议、数据库结构、权限及真实降级。行为变化先用已有覆盖或必要离线回归复现。复用已有工具，不安装依赖。
5. 子代理按自己的文件范围修改及回归，保持别人的修改；父代理整合并逐项核验全部清单的遗漏、重复、实际函数绑定、当前源码位置与指纹。新增函数也必须审阅，移除函数记录实际替代及引用情况。
6. 冻结源码后运行相称的格式、lint、类型、语法、静态与离线测试，并单独列出未实测的平台/外部服务边界。交付可查看的逐函数结论、实际改动及证据。

沿用用户指定的两个已有子代理，不启动第三个。不创建 worktree，不重置/提交/推送，不启动真实服务、调用供应商、安装依赖或执行迁移；保留前端、数据缓存和其他任务的暂存修改。
