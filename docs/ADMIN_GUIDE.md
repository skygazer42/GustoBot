# 知识管理后台

Compose 部署后访问 `http://localhost:8000/admin.html`。使用 Vite 开发时，后台地址为 `http://localhost:5174/admin.html`。问答界面使用同一地址的根路径。

在后端配置 `GUSTOBOT_ADMIN_PASSWORD` 和独立随机的 `SECRET_KEY`（至少 32 字节）可启用单管理员登录。密码只由后端校验，登录有效期为 8 小时。刷新后继续当前管理页面；页面右上角可退出登录。登录页、后台 API 和 Cookie 通过同源的 `/api` 代理访问，部署时需配置反向代理，HTTPS 部署使用安全 Cookie。

密码或签名密钥变更后，旧会话失效。退出登录清除当前浏览器的 Cookie；已复制的令牌在过期或密钥变更前仍有效。

## 补充资料

打开「向量知识库」，点击「添加文档」，可选择上传文件或粘贴文本。

上传交给当前运行的 GustoBot 实例。Compose 将上传原件和入库后的数据存放在本机 Docker 卷，直接运行 Python 时，上传原件位于项目的 `uploads/`。[存储位置](DEPLOYMENT.md#默认服务)

- **上传文档**支持 TXT、Markdown、CSV、JSON、LOG、PDF、DOCX，最大 50 MB。服务解析正文、切块并将向量写入 Milvus。扫描版 PDF 需先做 OCR。此处上传的 CSV、JSON 作为原文资料进入向量检索。
- **粘贴文本**需要填写名称与正文，提交后经过相同的切块和向量入库流程。同一草稿重试沿用来源身份。

结构化记录从「菜谱与做法」的「添加菜谱」导入。填写菜名与菜谱 JSON 对象后，服务按已有字段映射直接写入 Neo4j。字段包括「主食材」「辅料」「做法」「耗时」等，格式可参考 `web/tests/fixtures/admin-recipe.json`。

入库成功后自动打开新来源。失败时保留输入，重试可以复用已上传的文件。文档目录显示每个来源的最新内容版本，支持按名称搜索、按状态筛选和分页。

## 修改文档与更新检索

选择文档后点击「编辑原文」，可修改资料名称和完整正文，再点击「保存并更新检索」。编辑器单独读取完整正文，最多支持 1,000,000 字符；超限明确拒绝，不用 20,000 字符预览覆盖原文。关闭未保存的编辑会询问是否放弃，保存失败会保留草稿。

正文修改生成新的内容版本并重新切块、向量化。旧版本的原文和向量保留，检索使用该来源当前已发布的版本；新版本入库失败或取消时，原来已发布的版本仍可检索。仅修改名称时复用已核对的切片回执，不重新生成向量。保存成功后该文档参与检索；正在入库、来源已更新或编辑快照已变化时，服务返回冲突，需刷新核对。

来源网址、许可和实体关联会保留。已经写入的图谱事实和原始证据独立保留，编辑正文不会自动修改图谱，也不能用新正文覆盖既有图来源。修改涉及图谱证据时，需按图谱流程重新核对。正文改回已存在的历史版本暂不支持，会明确提示冲突。

## 核对原文与图谱

选择文档后，在右侧阅读区查看 Milvus 中的原文切片和解析、切块、向量入库记录。手机按上下顺序排列。切片按当前来源版本的成功入库回执定位。失败重试或撤回后，可核对该版本已入库的历史切片。入库记录显示已保存的处理结果。

展开「查看来源原文」或历史入库任务可查看详情。原文预览最多 20,000 字符，抽取与重试由服务端读取完整记录。点击「图谱核对」可检查该来源的图谱事实和抽取候选。

文档的“抽取图谱候选”显式调用一次模型；候选尚未入库，可修改实体类型、名称、关系端点和属性。证据、来源与记录身份保持只读。修改后点击“校验候选”，通过后才能“确认写入图谱”；服务端写入前还会再次校验。校验和写入不再次调用抽取模型。

抽取最多支持40000字符，超限需要拆分资料。来源身份已绑定其他内容时，图谱写入会返回冲突，不能通过覆盖证据或切换版本绕过。当前本体使用OWL/RDFS和SHACL；资源文件和来源映射仍在项目配置中维护。

## 浏览已入库图谱

「本体与图谱」默认打开「知识图谱」，从当前知识空间读取真实实体和有向关系。点击节点或连线可查看属性、关联关系及原文证据，支持缩放和平移。未选中记录时，右侧列出当前加载图谱的类型分布。超过8条关系时，关系名称在悬停、键盘聚焦或选中对应连线时显示。

搜索只查找当前已加载的实体和别名；「起点类型」筛选查询起点，关联的其他类型端点仍会显示。选中实体后「查看出向关系」以该实体为起点读取一跳关系，不包含双向邻域查询。读取达到数量或证据上限时会明确提示部分事实视图。

「本体图谱」展示当前定义中的业务类型和允许关系，点击类型或连线可核对含义、粒度与属性约束，底部「定义清单」可展开完整编译定义。它描述允许的类型结构，数量不代表已入库实例。

来源映射核对中的「查看已入库图谱」仅展示该来源精确版本支持的实体、关系与证据。文档向量化成功也不等于已完成图谱写入。

## 问答测试

填写实际问题后运行，查看回答、来源、请求耗时、返回的模型调用次数及执行明细。可添加预期文本进行人工对照。查询面向整个当前知识空间，页面会说明返回来源是否包含本次核对资料。

桌面左侧为测试设置，右侧为结果阅读区；手机按上下顺序排列。运行中继续编辑的草稿不会改变已经提交的问题和预期。传输失败会保留输入；若已有结果，会明确标记它是上次返回的结果，不能当作本次回答。长回答在桌面结果区内滚动，来源及执行明细可展开核对。

“需要确认条件”“未找到匹配记录”“本次查询未完成”与正常回答分别显示；HTTP请求成功不等于答案正确。同名菜谱有多份做法时，正式对话页会要求选择版本。后台的单问题测试不提供会话多轮选择。

## 重试、撤回与当前边界

文档可重新入库；“撤回文档检索”保留原文及任务历史，停止该来源的文档检索，已经写入的图谱事实仍保留。已撤回文档可恢复入库。后台不提供图谱删除、本体编辑、任意SQL/Cypher执行、XLSX字段映射或批量评测调度。

文档列表每行右侧的「删除」和阅读区的「删除文档记录」使用相同操作。确认弹窗列出文档名称和入库时间，方便区分同名记录。确认后删除该来源的全部已确认版本、入库任务和当前向量库中的对应切片；已撤回文档也可删除。已发布的图谱事实、证据及独立上传原件保留。正在入库的文档需等任务结束后再删除；确认后出现新版本时需刷新并重新确认。删除失败或请求超时时，需刷新核对实际记录及检索状态，记录可能已停止检索，仍存在的记录可重试删除。删除成功后无法通过“恢复文档入库”找回记录，需要重新添加资料。

「已停止检索」表示下架，原文和向量仍在；它与永久删除是两种不同操作。后台按原文管理文档向量，不提供直接手改浮点向量或任意清空集合的操作。

来源读取、原文核对和本体校验不调用模型。文档向量化需要embedding服务；抽取和需要语义分析的问答使用已配置的模型服务。

当前采用单管理员密码，没有多用户角色。未设置管理员密码时沿用本地免登录模式。启用登录后，来源管理、知识入库、撤回及图谱写入要求管理员会话；聊天和知识查询仍可直接使用。
