# 领域无关知识服务实施计划

日期：2026-11-15。依据：用户已授权开始合并与本体约束实现，补充要求核心可用于任意领域，菜谱作为可替换配置，并在完成后交付实际流程图。

## 目标与实现边界

保留一个 LightRAG 第三方服务；领域名称、范围、路由词、实体类型、关系起终点和属性要求从 JSON 领域定义加载。现有菜谱专属工具迁至显式领域装配模块；无专属工具的领域直接复用公共文档图问答，不连接菜谱库。提供确定性的事实校验、有来源的结构化事实入库与有界关系查询。继续使用已有 Pydantic、LangChain/LangGraph、LightRAG 和 Neo4j，不安装新框架，不重建旧索引，不执行线上迁移。

领域约束不能依靠 prompt 承诺：模型抽取后校验类型、属性、关系起终点、实体引用及原文引证；Neo4j 使用独立领域命名空间、参数化查询与有界路径。LightRAG 文档关系检索保留现有答案语义，显式与强约束事实查询区分。

## 并行职责

1. 服务合并：`application/services/lightrag_service.py`、`components/customer_tools/{node,__init__}.py`、LightRAG 直接脚本调用方及相关回归。唯一运行时、延迟导入、并发初始化、失败与取消清理；HTTP/SSE、索引维度和部分成功契约保持可观测。
2. 领域定义：`domain/knowledge.py`、`config/domain.py`、`config/domains/*.json` 和领域行为测试。Pydantic 定义、关系与事实校验、证据引用、确定性的有界子图提取；至少设备领域和菜谱领域使用相同核心。
3. 主代理集成：settings、提示与路由、菜谱工具装配模块、Neo4j 通用事实存储、知识服务/API、回归与流程图。核心不通过领域 ID 判断业务，配置中的专属工具模块只有被显式选择时才加载。

## 顺序与验收

- 修改前运行已有离线基线；各职责先补行为回归，再实现。
- 合并调用方与资源所有权：两个并发首次请求只初始化一次；单次 Agent 不关闭共享索引；失败可重试；取消保持可见；CLI 独立关闭。
- 从入口移除菜谱专属提示与固定范围；根据领域配置构造主路由、补充信息、图问答与 KB 范围；旧菜谱装配保持可选可用。
- 提供领域定义读取、事实抽取/校验/插入、有界图查询端点；以原文片段作为证据，禁止未知实体类型、关系、属性、悬空引用和无原文引证的数据写入。
- Neo4j 新事实仅写领域命名空间，不删除旧节点；查询每一跳都按领域及允许关系约束，参数不拼接为 Cypher 标识符。单次写入事务一致；驱动按请求拥有并关闭。
- 用设备/组织等非菜谱数据跑同一套抽取、校验、存储边界和查询测试；验证核心路径不构造菜谱检索器或连接菜谱库。
- 运行全部离线测试、Black、Flake8、Mypy、Ruff F/E9及差异检查。测试替换外部边界，不读取真实 `.env`、调用在线模型或生产数据库。真实联测未覆盖的部分在交付中明确。
- 根据实现生成 Mermaid 流程图并记录启用/替换领域的配置示例；不将计划画成已实现能力。
